# Ledger Web

Angular client of the Ledger API. It covers every feature: summary with **charts** (month, year or custom period), wallets (opening balance and balance adjustments), transactions (with filters), categories, contacts, loans, **existing debts**, splits, groups with simplified balances, settlements and pending wallet assignments. Everything can be **edited, deleted and restored** with a reason and a full **history**; changes to shared operations are **reviewed** by the linked users involved; there is an **Activity** page and a **lock date** in Settings. Every form has a **When** field (date and time; future dates not allowed). It is available in **English and Spanish** and has **light and dark** themes, and it works on desktop and on phones.

| | |
| --- | --- |
| Framework | Angular 22: standalone components, signals, zoneless, strict templates |
| Styling | Tailwind CSS 4 on **design tokens** (one file for the palette, one for the light/dark theme) |
| Components | Own UI kit (`src/app/ui`); Angular CDK only for dialog behaviour |
| i18n | Angular built-in i18n: one build per language, served at `/en/` and `/es/` |
| Auth | Keycloak through `angular-oauth2-oidc` (authorization code + PKCE, automatic token refresh) |
| State | Angular signals, `rxResource` and small services (no store library) |
| Tests | Vitest (unit) and Playwright (end-to-end against the real stack) |

## Run it

### Prerequisites

* Node.js 24 and npm 11
* The Ledger backend (see the [root README](../../README.md)): PostgreSQL, RabbitMQ and Keycloak (`docker compose up -d --wait postgres rabbitmq keycloak`), migrations applied, and the **API running on http://localhost:5209**.

### Development server

```bash
cd clients/web
npm ci
npm start            # English, http://localhost:4200
npm run start:es     # Spanish, http://localhost:4200
```

Log in with **alice/alice** or **bob/bob**. The dev server proxies `/api` and `/health` to `http://localhost:5209` (`proxy.conf.json`), so the browser calls the API on the same origin and the API needs no CORS.

> `ng serve` serves **one language at a time**. In dev, the language switcher leads to a page that does not exist; to try both languages together, use the container (below).

### In VS Code

| Launch configuration | What it does |
| --- | --- |
| **API + Web** | Starts the infrastructure, applies migrations, then debugs the API and opens Chrome on the app with breakpoints in the TypeScript code. |
| **Web (Chrome)** / **Web (Chrome, Spanish)** | Starts `ng serve` (English or Spanish) and debugs the app in Chrome. The API must already be running. |

Tasks: `web: install`, `web: start`, `web: start (es)`, `web: test`, `web: e2e`.

### Container (both languages)

```bash
docker compose --profile full up -d --build     # from the repository root
```

The web app runs at **http://localhost:4201**. nginx serves `/en/` and `/es/`, redirects `/` (and any path without a language) to the language chosen last (the `ledger_locale` cookie, English by default), and proxies `/api` to the API container.

## Design system

### Change the colors or the look

All colors come from **`src/styles/tokens.css`** (the palette) through **`src/styles/theme.css`** (what each color is used for).

* **Change the brand color:** replace the `--palette-accent-*` values in `tokens.css` (currently Tailwind's *indigo* scale). Nothing else needs to change.
* **Change the grays or status colors:** edit the `--palette-neutral-*`, `--palette-success-*`, `--palette-danger-*` or `--palette-warning-*` values.
* **Change the corner radius or the font:** edit `--radius-base` or `--font-family-base`.
* **Change the chart colors:** edit `--palette-chart-1…8` (series such as categories or wallets). Income and expense bars use the success and danger colors; the net worth line uses the primary color.
* **Change what a color is used for** (e.g. a darker background in dark mode): edit `theme.css`, which has the light values in `:root` and the dark values in `:root.dark`.

Components never use raw colors: they use semantic Tailwind utilities generated from the theme, such as `bg-surface`, `bg-surface-muted`, `text-foreground`, `text-muted`, `border-border`, `bg-primary`, `text-primary-foreground`, `bg-primary-soft`, `text-success`, `text-danger`, `bg-warning-soft`, `rounded-ui` and `ring-ring`.

### Light and dark

`ThemeService` follows the operating system by default. The button in the top bar cycles **system → light → dark**, and the choice is stored in `localStorage` (`ledger.theme`). A small script in `index.html` applies the theme before Angular starts, so there is no flash.

### Hide amounts

The eye button in the top bar (or **Shift+H**, except while typing in a field) hides sensitive figures, e.g. while sharing the screen: money amounts keep their currency but show `•••••` (`€•••••`, `••••• €`), asset quantities and unit prices are masked, and charts keep their shapes but lose the numbers on the value axis and in tooltips. The choice is stored in `localStorage` (`ledger.hideAmounts`). `PrivacyService` (`core/privacy`) holds the state; `MoneyPipe`, `PricePipe` and `QuantityPipe` are impure so they update when it changes, and `ChartView` redraws masked. Amounts typed or prefilled in form fields stay visible, and green/red colors still show whether an amount is positive or negative.

## Internationalization

Angular's built-in i18n: texts are translated **at build time**, and each language is a separate build (`/en/`, `/es/`).

* **Templates:** `i18n="@@feature.key"`, and `i18n-<attribute>="@@feature.key"` for attributes such as `heading`, `label`, `placeholder` or `aria-label`.
* **TypeScript:** `` $localize`:@@feature.key:Text with ${value}:name:` ``.
* **Always use a custom id** (`@@…`), so translations survive text changes.

To add or change texts:

```bash
npm run i18n:extract                  # updates src/locale/messages.xlf
```

Then add or update the matching `<trans-unit>` with its `<target>` in `src/locale/messages.es.xlf`. Keep the `<x id="…"/>` placeholders exactly as they are in the source. The build fails if a Spanish translation is missing (`i18nMissingTranslation: error`).

To add another language:
1. Add it under `i18n.locales` in `angular.json`, with its translation file and base href.
2. Add it to `LOCALES` in `core/i18n/locale.service.ts`.
3. Add it to the `map` in `nginx.conf` and to the `location ~ ^/(en|es)/` rule.

Amounts and dates follow the language (`€1,234.50` / `1234,50 €`). The labels of API codes (transaction kinds, statuses, system account names) and the messages of known API error codes are translated in `core/i18n/labels.ts` and `core/api/error-messages.ts`.

## How the app talks to the API

* **Authentication:** nothing renders until the user is logged in (`provideAppInitializer` → `AuthService.init()`). The OAuth interceptor adds the access token to `/api` requests and refreshes it before it expires. Keycloak client: `ledger-web` (public, PKCE, redirects `http://localhost:4200/*` and `http://localhost:4201/*`).
* **Errors:** `apiErrorInterceptor` retries `503 Not available yet` (a module still catching up) and shows other errors as a toast in the user's language.
* **Eventual consistency:** after any change, `DataChanges.notify()` reloads the pages now and once more 1.5 s later, when the other modules have caught up (e.g. wallet balances). New wallets show *Setting up…* until the ledger has them.
* **Dates** are chosen in local time and sent in UTC (`core/dates.ts`). The reports send the browser's IANA time zone, so days and months are cut where the user lives.
* **Dashboard charts** (`features/dashboard/report-panel`): Month / Year / Custom with previous and next, and a currency selector (default: the currency with the most activity). Balance adjustments are not counted as income or expenses.
* **Loans, splits, settlements and existing debts** are asynchronous in the API (*fire and notify*): the dialog closes as soon as the API accepts the operation, a toast says it is processing, and `OperationTracker` polls it and shows the result (recorded, or rejected with the reason).

* **Edits** never modify anything: the API records a new version. Transactions are corrected synchronously; changes of shared operations return a change that is either *waiting for confirmation* (a toast names who must answer) or being applied (`OperationTracker.submitChange` polls the operation's history until it is applied or failed). `OperationActions` (`features/debts/operation-actions.ts`) opens the right edit dialog for each kind; the dialogs for recording (lend, existing debt, split, income/expense, transfer) have an edit mode with a required **Why?** (`ui/reason-field`).

## Tests

```bash
npm test                         # unit tests (Vitest), watch mode; `npm test -- --watch=false` for a single run
npm run e2e                      # end-to-end (Playwright) against ng serve + API + Keycloak
E2E_BASE_URL=http://localhost:4201/en/ npm run e2e    # same, against the container (also tests the language switch)
```

The first time, run `npx playwright install chromium`. The end-to-end tests log in as **alice** and create uniquely named wallets, contacts and groups in her account every time they run.

## Known limitations

* Some texts are **generated by the API in English** and shown as they are, e.g. the descriptions of settlements ("Trip: Carl paid Alice"), "Opening balance" and trades without a description ("Buy 0.5 BTC"). Errors without a known code also use the API's English message.
* The language switcher only works where both builds are served (the container). `ng serve` serves one language.
* The API URL is always `/api` on the same origin, and the Keycloak issuer is set in `app.settings.ts`: both are fixed at build time.
